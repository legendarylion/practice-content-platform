# ICP/Questionnaire to Website Content Map

Website copy has no platform-imposed character limits, so this map is
structural (which page, which section) rather than field-by-field like the
directory modules. Positioning source is the same ICP
(`_templates/icp-profile-template.md`) used for every other deliverable.

| Page / section | Primary ICP/questionnaire source |
|---|---|
| Homepage hero + subhead | ICP Ideal Client (who they are, what brings them in, in-their-own-words phrasing) - lead with symptom/outcome language, same rule as PT's first 270 characters. |
| Homepage "who we help" | ICP Ideal Client + intake 2.2 issues known for, 2.1 services offered. |
| Homepage differentiation / "why us" | ICP Differentiation section. |
| About / meet the clinician(s) page | ICP Trust & Authority Assets + intake 2.5 Identity & Credentials, Education. One page per clinician for a group practice. |
| Approach / how we work page | ICP + intake 2.5 "describe your approach in plain language" - same source PT's Part 2 draws from, expand it here instead of compressing it. |
| Service pages (one per offered service) | Intake 2.1 services offered, 2.4 fees/session length per service, ICP niche. |
| FAQ page | Intake 3.2 Conversion Behavior (questions prospects ask, reasons they don't move forward, reassurance language) - use word-for-word where possible, same as the PT "Intro to new clients" note. |
| Fees / getting started page | Intake 2.4 fees & payment + 3.1 lead handling ("what happens after someone reaches out"). |
| SEO targeting | Intake 4.2 SEO brief (service areas, local competitors) layered on top of ICP keywords/client language - do not re-ask what 2.2/2.3 already captured. |

## Reference example

`clients/michael-lydon/deliverables/website-content/source/Realization
Process - Michael Lydon - Home Page Content (Client Written, MHM
Reviewed).docx` (git-ignored like every `.docx` in this repo, not part of
this module's tracked templates) is a real, delivered homepage built outside
this tool's template format. It's a useful quality/tone bar - notably its build
notes call out putting zero SEO keywords in the H1/subhead on purpose,
carrying them in the meta description and body copy instead, since the H1 is
"the billboard, not the search-engine copy." Worth reading before drafting a
first homepage through this module, even though its structure doesn't match
`template.md` block-for-block.

## Cross-checks this map encodes

- **Voice consistency across surfaces.** The words-to-use/avoid lists in the
  ICP apply here exactly as they do to directory profiles - a website that
  says "journey" while the PT profile avoids it (per client instruction) is
  the same trust contradiction this project exists to prevent, just on a
  different surface.
- **Licensure/credentials display.** Must match the directory profiles'
  verification sections and each other, same rule as PT's Credentials note.
- **CTA consistency.** One consult length/format, one primary CTA (3.3),
  used identically across the website and every directory profile.
